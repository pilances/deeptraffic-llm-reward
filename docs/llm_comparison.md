# Matched LLM, DQN and rule-policy comparison

The first comparison uses the user-selected **three episodes of 200 frames**,
with eleven controlled/scored cars, twenty cars in total, seven lanes, and the
unchanged observation `(lanes_side=6, patches_ahead=52, patches_behind=0)`.
Seeds `2000100, 2000101, 2000102` were fixed before inspecting the scores.
Every policy starts a fresh Gymnasium environment per seed. The engine suspends
inside each callback while the LLM is answering; inference time does not advance
simulation time. All policies act at every native callback, without action reuse
or a reduced decision frequency.

Policies:

- `llm`: local `qwen3:8b`, Q4_K_M, existing state-v1 prompt and strict parser,
  temperature 0, decoding seed 42, thinking disabled, 64 output tokens,
  context 8192, no exploration, retries, response cache or fallback actions.
- `dqn_submission`: supplied frozen ConvNetJS linear Q network `676 -> 5`,
  evaluated as float64 `argmax(W @ observation + b)`. These are the same weights
  previously reproduced at 75.80 mph on the 500-episode JavaScript protocol.
  This is not one of the separately trained five-car PyTorch checkpoints.
- `rule`: unchanged observation-only `RuleBasedPolicy`, instantiated with the
  same observation dimensions as the other policies.

The engine retains its historical scheduling: eleven cars count toward the
score, but only cars 0–9 receive independent callbacks. Car 10's native action
propagation is unchanged for all policies. A 200-frame episode has 67 callbacks;
each policy therefore makes 201 decisions across the three scenarios.

The client now accepts `keep_alive_seconds`, with the original default of zero.
The comparison uses 300 seconds so the model remains loaded between requests.
This changes model residency, not prompts or decoding settings. Two diagnostic
requests are recorded separately in `results/llm_latency_warm_v1.jsonl` and do
not enter the comparison. They still took roughly 24–28 seconds each, dominated
by reading the large state prompt rather than generating the short answer.

Scores are the average controlled-fleet speed over every frame, floored to two
decimal places per episode. The reported median is the upper-middle order
statistic. Paired differences use the same seed in each policy. Individual
vehicle averages and action counts are also saved. Three short scenarios are
an exploratory measurement, not evidence of general superiority.

The **76.6 mph historical target** is retained as user-supplied context. Its
original checkpoint and complete evaluation conditions are unavailable here.
In particular, 200-frame independent resets are not the 2,000-frame,
500-episode sequential evaluation used for our historical reproduction. A
numerical difference to 76.6 must not be described as winning or losing that
benchmark. The previously reproduced 75.80 mph result also belongs to that
different, longer protocol.

Run from the nested project checkout:

```sh
OPENBLAS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 .venv/bin/python scripts/evaluate_llm.py
```

Results are written under `results/llm_comparison_short_v1/`:

- `manifest.json`: frozen environment, scenario seeds, model digest, server
  version, decoding configuration, prompt hash, source hashes and checkpoint hash.
- `checkpoint.json`: an exact copy of the evaluated DQN checkpoint.
- `<policy>_<seed>.jsonl`: every executed action, input-state hash, resulting
  state hash, reward and timing; LLM entries additionally contain complete
  prompts, raw server responses and parser decisions.
- `<policy>_<seed>.json`: completed episode statistics.
- `progress.json`: current completion/error status.
- `comparison.json`: final matched results and paired differences.

The files are generated by the script; retain them as evidence for reported
scores. They can be regenerated into a new directory using `--out`. No training
or prompt selection occurs during this experiment.

An interrupted run can be resumed with the exact same arguments plus `--resume`.
Existing actions are replayed without LLM calls, and every input/output state
hash, agent identity, frame and reward must match. Contract changes are rejected.
Transport or parser failures abort the run and are recorded in a separate
`.errors.jsonl`; unsuccessful attempts are never silently excluded from the
final score. Resume is explicit, not an automatic retry policy.

For an existing experiment, launch its resume in a separate operating-system
session with redirected input/output, independent of the terminal or chat:

```sh
.venv/bin/python scripts/start_llm_evaluation.py --resume
tail -f results/llm_comparison_short_v1/background.log
```

`background.json` records the process ID and exact command. The launcher reads
the frame count and seeds from the existing manifest. `progress.json` updates
after each complete episode; the decision journals grow after every successful
decision. On completion the runner writes `comparison.json` and marks progress
as `complete`. Errors are written to the log and progress file. No chat-based
monitor or scheduled automation is needed. Keep the Mac awake and Ollama running.

Tests cover interruption/resume equivalence, rejection of changed scenarios or
tampered outcomes, strict scenario pairing, and model-residency configuration.
They use the real environment with simulated policies; live measurements are
kept in the results directory rather than embedded in unit tests.
